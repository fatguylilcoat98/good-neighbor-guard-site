VeraCore

An evidence-focused verification engine that tests whether an answer is supportable — rather than simply generating convincing text. It treats language models as unreliable narrators and checks their claims.

See Example ResultsDiscuss VeraCore
Active Development

VeraCore is a working research system in active development. The examples below are illustrative of its approach; a public live endpoint is rate-limited and gated because verification uses multiple external models.

The core idea

Consensus is not certainty

Agreement between models increases probability, not truth. VeraCore routes a question through independent verification layers before returning a confidence-scored answer.

1 · Deterministic Anchor

If a question can be answered by computation — math, dates, unit conversions, physical constants — VeraCore never asks a model. Deterministic answers always override model consensus. Zero hallucination risk.

2 · Retrieval Consensus

Multiple models independently research the same question with enforced source diversity — each must cite sources from different epistemic classes (primary, curated, live, structured). Models can't self-police; exclusions are injected at the orchestration level.

3 · Adversarial Challenge

A dedicated model's only job is to find reasons the consensus answer is wrong — generating counterarguments, surfacing hidden assumptions, and flagging fabricated sources, wrong dates, or non-existent entities.

Honest scope

What VeraCore is — and isn't

VeraCore attempts to test whether an answer is supportable, not simply generate convincing text. It reduces — but does not eliminate — the risk of confident-but-wrong answers, and it is explicit about uncertainty. It is a research system in active development, not a certified fact-checking authority, and its confidence scores are estimates, not guarantees.
