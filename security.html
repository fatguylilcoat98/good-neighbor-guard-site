Security & Trust

Last updated: 2026 · How this site and its demos are kept safe.

This page describes a security philosophy and practices in good faith. It does not claim any formal certification. There is no SOC 2, ISO 27001, or equivalent audit, and no "enterprise-grade" guarantee is implied.

Philosophy

The Good Neighbor Guard builds around truth, safety, and accountability. That extends to how this site is run: public demonstrations are kept strictly separate from any production system, and nothing here is designed to expose credentials or user data.

Public demos are isolated from production

  • The CLASPION sandbox and VeraCore examples run entirely in your browser. They send no data to a server and perform no real-world action.
  • The public demos are not connected to any production CLASPION or VeraCore deployment, to the applications those systems govern, to real keys, or to any production database or filesystem.
  • Demos cannot execute code, delete files, send messages, make purchases, or take any external action.

Responsible handling of data

This marketing site does not run first-party analytics or collect account data (see Privacy). Contact forms compose email in your own client and store nothing here.

No intentional exposure of credentials

Secrets are not shipped in client-side code. If you believe you've found exposed credentials or a vulnerability, please report it (below) rather than acting on it.

Responsible disclosure

If you discover a security issue affecting this site or a Good Neighbor Guard system, please report it privately and give a reasonable time to remediate before any public disclosure. Do not access, modify, or destroy data that isn't yours, and do not run denial-of-service or automated attacks.

Security contact

Report security issues via the contact page (choose "General inquiry" and mention "security"). A dedicated security address will be published here once it is set up. Please include steps to reproduce and avoid sharing sensitive details publicly.
